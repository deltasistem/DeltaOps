FASE 1 — CORREGIR N-1

Problema:
listarTenants utiliza withGlobal sobre ten_tenants, tabla protegida por RLS.

Objetivo:
SUPER_ADMIN debe poder listar tenants sin depender de BYPASSRLS.

Investigar primero el contrato actual.

Implementar la solución de menor privilegio compatible con la arquitectura.

Preferencia:
usar un puerto/consulta administrativa explícita y fail-closed, no ampliar privilegios globales del runtime.

Si se requiere SECURITY DEFINER:

- función específica;
- owner deltaops_owner;
- search_path explícito;
- sin SQL dinámico;
- parámetros explícitos;
- solamente SELECT necesario;
- nunca aceptar tenantId desde frontend para elevar acceso;
- únicamente accesible desde el contexto autorizado de SUPER_ADMIN;
- registrar/auditar la decisión.

No modificar otras consultas withGlobal.

Agregar pruebas:
- SUPER_ADMIN puede listar tenants.
- TENANT_ADMIN no puede listar tenants de plataforma.
- SUPERVISOR/PLANIFICADOR/TECNICO/CONSULTA no pueden.
- anónimo no puede.
- tenant context no puede utilizarse para elevar privilegios.

FASE 2 — CORREGIR N-2

tenantId debe provenir exclusivamente del contexto autenticado/UoW/aggregate válido.

Nunca:
- body;
- frontend;
- parámetro libre;
- identidad proporcionada por cliente.

Agregar pruebas:

2. ambos puntos de emisión contienen tenantId.
3. replay conserva tenantId.
4. /sync conserva tenantId.

No inventar tenantId para los 163 eventos históricos.
