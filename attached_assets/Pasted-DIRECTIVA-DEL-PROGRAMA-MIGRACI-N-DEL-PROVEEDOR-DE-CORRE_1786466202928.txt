DIRECTIVA DEL PROGRAMA — MIGRACIÓN DEL PROVEEDOR DE CORREO A MICROSOFT GRAPH

Como Dirección del Programa se determina que DeltaOps NO utilizará SMTP para el envío de notificaciones Microsoft 365.

El proveedor oficial de correo será:

MICROSOFT GRAPH API
OAuth 2.0 Client Credentials
Application Permission: Mail.Send

La decisión es arquitectónica y debe implementarse respetando el diseño de DGP-017.

==================================================
1. OBJETIVO
==================================================

Reemplazar exclusivamente el adaptador concreto de correo Microsoft 365 basado en SMTP por un adaptador basado en Microsoft Graph.

NO modificar:

- NotificationPort
- EmailNotificationPort
- dominio de notificaciones
- contratos de los módulos
- identidad de DeltaOps
- autorización propia de DeltaOps
- multitenancy
- roles
- permisos

- tenants
- Workflow
- Activos
- Órdenes
- Inventario
- Dynamic Forms
- módulos congelados

La plataforma DeltaOps continúa siendo completamente autónoma.

Microsoft 365 será ÚNICAMENTE proveedor externo de transporte de correo.

3. AUTENTICACIÓN
==================================================

Utilizar exclusivamente:

OAuth 2.0 Client Credentials

Token endpoint:

POST
https://login.microsoftonline.com/{GRAPH_TENANT_ID}/oauth2/v2.0/token

Content-Type:

application/x-www-form-urlencoded

Parámetros:

grant_type=client_credentials
client_id={GRAPH_CLIENT_ID}
client_secret={GRAPH_CLIENT_SECRET}
scope=https://graph.microsoft.com/.default

Cachear el access token hasta su expiración y renovarlo cuando corresponda.

Nunca solicitar un token por cada correo.

Nunca almacenar tokens persistentemente.

Nunca escribir tokens o secretos en logs.

==================================================
4. VARIABLES / SECRETS
==================================================

Utilizar Secrets del entorno:

GRAPH_TENANT_ID
GRAPH_CLIENT_ID
GRAPH_CLIENT_SECRET
GRAPH_SENDER

GRAPH_SENDER representa exclusivamente el buzón remitente autorizado.

NO pedir contraseña del buzón.

NO crear:

SMTP_HOST
SMTP_PORT
SMTP_USER
SMTP_PASS

NO utilizar SMTP.

Si ya existen variables M365_* correspondientes al proveedor SMTP, no las reutilices para Graph.

Puedes conservarlas temporalmente para compatibilidad si el código lo requiere, pero el proveedor activo de producción debe ser Graph y no SMTP.

6. ENVÍO
==================================================

Utilizar:

POST
https://graph.microsoft.com/v1.0/users/{GRAPH_SENDER}/sendMail

Headers:

Authorization: Bearer <access_token>
Content-Type: application/json

Body:

{
  "message": {
    "subject": "<subject>",
    "body": {
      "contentType": "HTML",

    "toRecipients": [
      {
        "emailAddress": {
          "address": "<recipient>"
        }
      }
    ]
  },
  "saveToSentItems": true
}

- destinatarios
- asunto

- CC
- BCC

- idempotencyKey

Si el contrato actual del EmailNotificationPort soporta adjuntos, conservar el contrato y mapearlo correctamente a Microsoft Graph.

No modificar el contrato únicamente para acomodar Graph.

==================================================
7. RESPUESTAS
==================================================

Considerar:

202 Accepted = envío aceptado correctamente por Microsoft Graph.

No asumir que 202 significa que el destinatario ya recibió el correo.

Registrar el resultado operacional correspondiente sin exponer información sensible.

Errores:

401:
problema de autenticación/token.

403:
permiso Mail.Send, consentimiento o autorización de acceso al buzón.

404:
buzón GRAPH_SENDER inexistente/no accesible.

429:
throttling de Microsoft Graph.

5xx:
error temporal del servicio.

Aplicar reintentos únicamente cuando sean seguros y de acuerdo con el mecanismo de outbox/idempotencia existente.

No crear un sistema paralelo de reintentos si DGP-017 ya posee uno.

10. RBAC DE EXCHANGE
==================================================

La Dirección del Programa quiere que el acceso de la aplicación al correo quede restringido al buzón remitente cuando sea posible.

NO implementes todavía comandos destructivos ni cambies la configuración de Exchange.

Inspecciona/documenta si la aplicación tiene configurado:

Exchange Online RBAC for Applications

con el rol:

Application Mail.Send

y un scope limitado al buzón GRAPH_SENDER.

Microsoft está orientando el control de acceso de aplicaciones de Exchange hacia RBAC para aplicaciones.

Si actualmente el tenant ya tiene configurada una restricción equivalente para la aplicación, reutilízala.

Si no existe:

NO inventes valores.

NO ejecutes PowerShell contra Exchange.

Reporta exactamente qué configuración falta para limitar Mail.Send al buzón remitente.
