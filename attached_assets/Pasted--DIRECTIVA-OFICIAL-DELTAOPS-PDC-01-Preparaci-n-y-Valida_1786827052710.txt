# DIRECTIVA OFICIAL — DELTAOPS
# PDC-01 «Preparación y Validación para Producción Controlada»

## 0. CAMBIO DE ETAPA

DELTAOPS LITE HA TERMINADO SU ETAPA DE DESARROLLO.

A partir de esta directiva NO se deben crear nuevas funcionalidades de negocio.

El objetivo ahora es preparar DeltaOps Lite para una PRODUCCIÓN CONTROLADA.

La filosofía cambia de:

DESARROLLAR

a:

PREPARAR → VERIFICAR → PROTEGER → DESPLEGAR CONTROLADAMENTE → OBSERVAR

No crear LITE-12.

No crear nuevos módulos.

No agregar funcionalidades por iniciativa propia.

No ampliar el alcance del producto.

No convertir DeltaOps Lite nuevamente en un CMMS/ERP sobredimensionado.

# 4. BACKUP — BLOQUEANTE

LITE-11 dejó pendiente:

"Verificar y ensayar backup/restauración con el proveedor de la plataforma."

Esto debe investigarse y documentarse.

Determinar:

1. ¿Quién aloja actualmente la base de datos?
2. ¿Qué mecanismo de backup proporciona?
3. ¿Qué frecuencia tiene?
4. ¿Cuál es la retención?
5. ¿Es automático?
6. ¿Cómo se solicita una restauración?
7. ¿Se puede restaurar a una base independiente?
8. ¿Cuál es el RPO?
9. ¿Cuál es el RTO?
10. ¿Existe snapshot/manual backup?
11. ¿Cómo se comprueba que el backup realmente sirve?

NO afirmar que existe un backup utilizable si no se ha comprobado.

# 6. HEALTH GATE

Corregir si todavía corresponde:

Deployment health gate:

/health

debe ser sustituido por:

/ready

cuando el proveedor/plataforma lo permita.

La razón es:

/health = proceso vivo

/ready = aplicación realmente preparada para atender solicitudes y dependencias críticas.

Verificar después del cambio:

- aplicación arrancando;
- DB disponible;
- /ready 200 cuando está lista;
- /ready no OK cuando la DB no está disponible;
- deployment reconoce correctamente el estado.

No modificar /health innecesariamente.

# 18. PRUEBA DE USUARIO PILOTO

NO desplegar inicialmente a toda la organización.

Definir un piloto controlado.

Idealmente:

- un centro;
- pocos usuarios;
- algunos activos reales;
- operación real.

No es necesario crear un nuevo módulo piloto.

El piloto es simplemente una estrategia de despliegue.

---

# 19. CASO OPERACIONAL PILOTO

Ejecutar con usuarios reales:

### Día operacional

1. Login.
2. Home.
3. Seleccionar equipo.
4. Registrar horómetro.
5. Revisar rutina.
6. Ejecutar preoperacional.
7. Obtener APTO/NO APTO.
8. Si existe hallazgo, generar mantenimiento.
9. Ejecutar OT.
10. Registrar mano de obra.
11. Registrar repuesto/insumo.
12. Registrar combustible cuando aplique.
13. Validar.
14. Cerrar.
15. Consultar hoja de vida.

Debe sentirse natural para un trabajador.

# 28. PLAN DE ROLLBACK

"volver a superusuario".
